# Examples and case handoff

All requests below are hypothetical. They supply workflow examples, not observed images, numerical camera calibrations or executable processing recipes.

## New DSLR, no calibration frames, mixed phases

Example request: “I have a three-exposure eclipse bracket, some partial-phase frames and no flats. I want an editable photograph.”

Inventory only the selected sources within the user's authorization. Separate totality, contact and uncertain phases; keep the uncertain group out of a qualified stack. Do not reject all photography merely because flats are absent, and do not manufacture a flat. Record the limitation and measure the camera's response and registration before proposing a declared stack. Ask only the missing questions that block the next authorized action. A camera's brand is not a transferable calibration.

## Mirrorless camera with distinct luminance and chroma support

Example request: “The faint outer corona has useful green signal, while red and blue are weak.”

Do not discard qualified green luminance solely to make RGB support uniform. Identify whether the output is measured RGB, luminance without qualified chroma, or a declared presentation colour choice. Obtain approval before adopting a material propagated-colour interpretation. The display must not imply measured RGB where it is absent. Propagated colour is a declared reconstruction: keep it in its own layer, with a mask of where colour was not measured, and say so in the caption. No specific propagation algorithm is provided by this skill.

## Existing preferred edit

Example request: “Keep my finished edit and give me adjustable detail layers.”

Follow AEL's existing-edit route. Decide whether new detail is recomputed on that presentation or existing layers are aligned. Preserve the original file, layer channels, colour profile and masks; separate presentation registration from scientific qualification. A Photoshop composite is not evidence of a retained linear RAW parent. If the requested route requires a missing parent, stop that route and explain available alternatives.

## Accepted master and a promising new metric

Example request: “A small test with the new NRGF has a better ring metric. Should it replace my accepted master?”

Keep the accepted file unchanged. A local software comparison does not show useful full-canvas photographic benefit. Propose a separately authorized new candidate only if the photographer wants a comparison; otherwise retain the negative or limited result and stop. Do not reopen scientific/lunar closeout by implication.

## Minimal case receipt

Use an ordinary case record; no application-specific database or orchestration is required. Include:

- Goal, authorized scope, camera/optical train, cohort/phase decisions and input identities.
- AEL/version/environment and declared recipe/config/source identities.
- Canvas/epoch and the five separate geometry/support roles.
- Measured versus operational qualifications, failed controls and unresolved questions.
- Output identity, editable controls, file checks, views inspected and actual native application evidence.
- Photographer decision and its exact scope. Leave application version or acceptance instant unspecified when not supplied.
- Independent photographic, scientific, lunar and reproduction status; protected dependencies and backup coverage.
- A concrete next action or STOP. A retained recipe is not proof of successful RAW-to-final or exact historical replay.

Human approval of an existing bounded stage remains valid; do not create a separate permission loop for each routine check. A new scientific claim, changed geometry/cohort, replacement of an accepted version or public submission needs the applicable new decision.

If a later explicit photographer acceptance supersedes an earlier HITL-ready report, append the new closeout; retain the older report as historical evidence. A filename containing “candidate” does not override accepted status. Rejection or STOP is a valid endpoint with evidence preserved.

## Scientific evidence request without publication

Example request: “Does my preferred edit establish physical Earthshine or absolute brightness? I want an evidence plan, not publication.”

Keep unsupported physical claims unqualified, preserve the photograph and identify the missing calibration, sky/stray-light and independent evidence. Route supported comparisons to the existing scientific specialist. Report the result locally; do not append publication or submission to that plan. A later publication request needs explicit approval of its exact content, files, destination and attribution. Scientific evidence requirements are unchanged.
