# Corona filter layers

Read [setup and operating instructions](../../docs/USAGE.md) before running AEL. This plugin holds instructions only: run the AEL 1.5.0 engine installed and checked as that guide describes. Respond in the user's language. Work on user-selected inputs and write new output directories.

Read [filter recipes](../../docs/DEVELOP.md), [field lessons](../../docs/FIELD_LESSONS.md), and [paper versus library](../../docs/PAPER_AND_LIBRARY.md). Copy [filters_config_template.json](../../examples/filters_config_template.json) to the workspace and replace its sample settings with measured values.

Inputs are a linear image, geometry, validity, geometric coverage and base alpha. A stretched JPEG or finished Photoshop composite is not a linear HDR master. If the user wants to keep a finished edit, preserve it and describe separately whether new detail is recomputed or an existing layer is aligned; consult the [existing-edit case study](../../docs/EXISTING_EDIT_CASE_STUDY.md).

Run `filters --config RECIPE --out NEW_DIR` with the installed engine (`PYTHON -m ael`), into a new directory. Use the requested filters, or explain the three default variants (NRGF, the edge-aware WOW and isotropic ACHF). Since 1.3.5 the default WOW is the edge-aware one (`wow_edge_aware`, called `wow_bilateral` up to 1.3.4), the author's operator with range weights taken from a guide; the plain WOW (`wow`, the default in 1.3.4) is optional. Next to a lunar limb that the data reach, recommend the edge-aware WOW; to use the plain WOW further out, suggest blending both layers with a feathered mask in Photoshop, never inside one layer. The ACHF layers are shown with a level and a spread per ring (`"achf_display": "global"` keeps the old display). The author's opacities are examples for his image, not calibrated settings for another eclipse. Known limitations: ACHF/WOW can make bands along straight data edges; the plain WOW draws rings and a band of weaker texture next to a lunar limb that the data reach; the edge-aware WOW keeps the limb clean but still inverts some faint detail in its worst sectors. With two independent stacks, check a layer's fine detail with `ael.gates.fine_detail_fidelity`. Inspect these areas and retain negative checks rather than claiming an artefact-free image.

**The inner limit (AEL 1.5.0).** With the Moon in the geometry, the command first makes one map of what is not corona (the lunar limb and its white rim, the chromosphere, prominences, Baily's beads) from the colour and brightness of the data, keeps every filter out of it, takes the hydrogen light out of what the filters read, and checks each layer against the map. Nothing has to be added to the recipe. After every run:

1. Read `gates.verdict` in the command's output. `PASS`: go on. `WARN`: read the warning next to the layer in the receipt (`gates.layers.NAME.inner_limit.warnings`) and look at that layer where it says. `FAIL`: `gates.failed` names the layer; if it was visible it was written switched off and is out of the preview (`switched_off_by_a_gate`); do not switch it on, find the cause. With `failed` empty, the layers do not start at the same place (`between_layers`). The Larson–Sekanina layers fail by construction (they leave out a band of their own next to the Moon). `NOT JUDGED`: no map was made; `inner_limit.why_not` says why (usually the geometry has no Moon: measure it with `geometry --input IMAGE --out GEOMETRY.json`).
2. Open `inner_limit_map.png`, enlarged, and show it to the user: corona grey, limb white, chromosphere pink, prominences red, beads cyan. Every red or pink pixel must be emission and no corona must be coloured. Read `inner_limit.warnings` aloud (with a mono input the map has no prominences, and says so).
3. Never add a margin or a feather to the map, never change a threshold to pass a layer, never hide a band along the limb by switching scales or filters off near it, never touch the geometry of the lunar limb. The corona between prominences and next to the limb is the detail the user wants.

The keys `"inner_limit": false` and `"edges": "classic"` give the layers of AEL 1.4.2 (except the NRGF, which carries a corrected chain with either value), for comparing with an image that already exists. Both WOW layers still draw bands along an edge of the data; the MGN, the isotropic ACHF, the local RHEF and the Hessian layer draw weaker ones than before. `fnrgf` (outside `"all"`; list it by name) is an NRGF whose mean and spread follow the angle. Method, figures and limits: [the inner limit](../../docs/INNER_LIMIT.md).

Apply filters across the whole observed rectangle. The band the moving Moon swept is not valid data: leave it out through the geometry or the validity mask, and measure its width for this observation. The inner-limit map then starts at the edge of what is left and takes no further margin. Do not replace missing data with reflected or generated pixels. ACHF works on log luminance after a smooth radial-profile subtraction, not independently on colour channels. Do not hide artefacts with new masks or smoothing.

Set `photoshop: true` only when a layered Photoshop file is wanted and the dependency is available. The 16-bit display/PSB is not the authoritative signed float master. Retain the NPY arrays, float TIFF, alpha and validity for scientific use. For PixInsight use `photoshop: false` and explicitly export/re-read float TIFF when needed.

Preserve the user's colour profile, masks, manual alignment and limb. Each proposed change is a separate layer or file. Verify PSB bytes with `ael.photoshop.verify` and distinguish that from native Photoshop rendering. Before opening a file in Photoshop, check inside the same script that it is not already open; use a uniquely named copy, save as a copy and close only the document opened by that script.
